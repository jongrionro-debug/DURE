# Report Assistant PRD

## 문서 목적

이 문서는 `dure`에 추가할 `보고서 작성 보조 기능`의 제품 요구사항을 정리한다.

기존 1차 MVP는 기관 운영자가 사업, 수업, 세션, 출석, 교육일지, 첨부 문서를 웹에서 관리하게 만드는 데 집중한다. 이 문서는 그 다음 단계의 차별화 기능으로, 이미 쌓인 운영 기록을 활용해 기관 운영자가 결과보고서 초안을 만들고 현황을 분석할 수 있게 하는 기능을 정의한다.

이 기능은 단순히 오프라인 수작업을 웹으로 옮기는 데서 멈추지 않고, 운영 데이터와 PDF 자료를 근거로 보고서 작성 시간을 줄이는 것을 목표로 한다.

## 문제 정의

기관 운영자는 사업 운영이 끝난 뒤 결과보고서, 성과보고서, 제출용 요약 자료를 작성해야 한다. 하지만 현재 업무에서는 필요한 자료가 여러 곳에 흩어져 있다.

- 강사가 제출한 출석 기록과 교육일지가 세션 단위로 쌓인다.
- 증빙 자료, 조사 결과, 사진대지, 외부 제출 자료가 파일로 따로 관리된다.
- 기관마다 보고서 목차와 제출 양식이 달라 하나의 고정 템플릿만으로는 대응하기 어렵다.
- 운영자는 기존 보고서 샘플을 참고하면서 수치, 활동 내용, 성과 근거, 누락 자료를 수작업으로 찾아야 한다.
- AI가 초안을 만들어도 출처가 없으면 외부 제출 문서로 신뢰하기 어렵다.

따라서 제품은 기관별 운영 기록과 PDF 자료를 보고서 작성의 소스로 삼고, 기존 보고서 샘플의 구조에 맞춰 출처가 달린 초안을 생성해야 한다.

## 제품 목표

기관 운영자가 기존 결과보고서 샘플 PDF와 `dure`에 쌓인 운영 기록을 바탕으로, 출처가 달린 결과보고서 초안을 생성하고 웹에서 섹션 단위로 편집한 뒤 DOCX/PDF로 내보낼 수 있게 한다.

성공 기준은 아래와 같다.

1. 운영자가 템플릿 PDF를 업로드해 보고서 프로젝트를 만들 수 있다.
2. 기간과 포함 사업을 선택하면 관련 세션, 출석, 교육일지, PDF 첨부가 자동 수집된다.
3. 운영자가 생성 전 소스 PDF를 제외하거나 보고서 전용 PDF를 추가할 수 있다.
4. 시스템이 템플릿 PDF에서 목차와 섹션 구조를 분석한다.
5. 시스템이 운영 데이터와 PDF 본문을 근거로 섹션별 초안을 생성한다.
6. 주요 주장, 수치, 요약에는 문단 또는 주장 단위 출처가 붙는다.
7. 출처 없는 문장과 누락 자료는 확인 필요로 표시된다.
8. 운영자는 섹션 본문을 편집하고 AI 재작성 요청을 할 수 있다.
9. 운영자는 보고서 작업공간 안에서 포함 자료에게 질문하고 답변을 섹션에 삽입할 수 있다.
10. 운영자는 최종 결과를 DOCX와 PDF로 내보낼 수 있다.

## 핵심 사용자

### 기관 운영자

1차 범위에서 이 기능은 `기관 운영자`만 사용한다.

기관 운영자는 자기 기관의 사업 운영 기록을 바탕으로 결과보고서 초안, 현황 요약, 성과 분석, 조사 자료 정리, 확인 필요 목록을 만들고 최종 문서로 내보낸다.

강사는 1차 범위에서 보고서 작성 보조 기능을 사용하지 않는다. 강사는 기존처럼 세션 출석, 교육일지, 첨부 문서를 제출하는 생산자 역할을 맡는다.

## 핵심 개념

### 보고서 프로젝트

보고서 프로젝트는 하나의 보고서 작성 작업 단위다.

보고서 프로젝트는 아래 정보를 가진다.

- 보고서명
- 기관
- 대상 기간
- 포함 사업 목록
- 템플릿 PDF
- 자동 수집된 세션/출석/교육일지/첨부 PDF
- 운영자가 추가 업로드한 보고서 전용 PDF
- 생성된 섹션 초안
- 문단/주장 단위 출처
- 확인 필요 목록
- export 결과

보고서 프로젝트 상태는 세 가지만 둔다.

1. `생성 전`: 템플릿, 기간, 포함 사업, 소스 자료를 선택하는 단계
2. `생성 중`: AI가 템플릿과 소스 자료를 분석해 초안을 만드는 단계
3. `생성 완료`: 웹에서 편집, 질문, 재작성, export가 가능한 단계

`검토 필요`는 별도 상태로 만들지 않는다. 생성 완료 화면 안에서 확인 필요 문장, 누락 자료, 출처 없는 주장을 표시한다.

### 템플릿 PDF

템플릿 PDF는 보고서 프로젝트 생성에 반드시 필요하다.

템플릿 PDF는 기존 결과보고서, 제출처 양식, 목차가 포함된 보고서 샘플을 의미한다. 시스템은 템플릿 PDF에서 목차, 섹션 구조, 문체, 분량, 반복 패턴을 분석해 새 보고서 초안의 구조로 사용한다.

템플릿 없는 빈 보고서 생성은 1차 범위에서 제외한다.

### 소스 PDF

1차 MVP에서 AI 분석 소스로 사용하는 파일 형식은 PDF만 지원한다.

PDF 소스는 두 종류다.

1. 기존 세션 첨부 PDF
2. 보고서 프로젝트 전용으로 추가 업로드한 PDF

HWP, HWPX, DOCX, XLSX, 이미지 파일은 1차에서 직접 분석하지 않는다. 사용자는 필요한 자료를 PDF로 변환한 뒤 업로드해야 한다.

스캔 PDF 처리를 위해 OCR은 1차 범위에 포함한다.

### 사업 선택

새로운 `사업/프로젝트` 마스터 개념은 만들지 않는다.

보고서 프로젝트 생성 시 운영자가 기존 사업 목록에서 포함할 사업을 다중 선택한다. 보고서명, 제출처, 외부 사업명처럼 보고서에만 필요한 값은 보고서 프로젝트의 텍스트 입력값으로 둔다.

## 핵심 사용자 흐름

### 1. 보고서 프로젝트 생성

기관 운영자는 보고서 작성 화면에서 새 보고서 프로젝트를 만든다.

필수 입력값:

- 보고서명
- 대상 기간
- 포함 사업
- 템플릿 PDF

선택 입력값:

- 제출처
- 보고서 설명
- 보고서 전용 PDF 자료

시스템은 대상 기간과 포함 사업을 기준으로 관련 세션, 출석, 교육일지, 첨부 PDF를 자동 수집한다.

### 2. 소스 자료 확인

생성 전 상태에서 운영자는 자동 수집된 소스 목록을 확인한다.

운영자는 아래 작업을 할 수 있다.

- 자동 수집된 세션을 제외한다.
- 자동 수집된 첨부 PDF를 제외한다.
- 보고서 전용 PDF를 추가 업로드한다.
- 생성 전 추가 업로드한 보고서 전용 PDF를 삭제한다.

생성 중에는 자료를 수정할 수 없다.

생성 완료 후에는 소스 파일을 고정한다. 자료를 바꾸려면 새 보고서 프로젝트를 만들어야 한다.

### 3. 초안 생성

운영자가 생성을 시작하면 프로젝트 상태는 생성 중이 된다.

시스템은 아래 작업을 수행한다.

1. 템플릿 PDF에서 목차와 섹션 구조를 추출한다.
2. 운영 데이터에서 기간/사업별 세션, 출석, 제출, 교육일지 데이터를 수집한다.
3. 세션 첨부 PDF와 보고서 전용 PDF의 본문을 추출한다.
4. 스캔 PDF는 OCR로 텍스트를 추출한다.
5. 템플릿 섹션별로 관련 소스를 검색한다.
6. 섹션별 초안을 생성한다.
7. 문단 또는 주장 단위로 출처를 연결한다.
8. 출처가 부족한 문장, 채우지 못한 섹션, 필요한 추가 자료를 확인 필요 항목으로 표시한다.

템플릿 분석이 실패하면 사용자가 섹션 목록을 직접 확인하거나 수정할 수 있어야 한다.

### 4. 생성 완료 작업공간

생성 완료 상태에서 운영자는 보고서 작업공간을 사용한다.

작업공간은 아래 영역을 포함한다.

- 섹션 목록
- 선택한 섹션 본문 편집 영역
- 문단/주장 단위 출처 표시
- 확인 필요 목록
- 자료에게 질문하기 패널
- export 버튼

1차 MVP는 완전한 워드프로세서를 만들지 않는다. 표지, 목차 점선, 페이지 번호, 세밀한 인쇄 서식 편집은 export 후 DOCX에서 마무리하는 흐름을 기본으로 한다.

### 5. 섹션 편집과 AI 재작성

운영자는 생성된 섹션 본문을 직접 수정할 수 있다.

섹션 단위로 아래 AI 요청을 할 수 있다.

- 다시 작성
- 더 공식적으로 작성
- 짧게 요약
- 더 자세히 작성
- 근거를 더 반영
- 확인 필요 문장 줄이기

섹션별 AI 재작성은 현재 보고서 프로젝트에 포함된 소스만 사용한다. 새 자료를 반영하는 증분 재분석은 1차 범위에 포함하지 않는다.

### 6. 자료에게 질문하기

자유 질의응답은 독립된 AI 자료실이 아니라 보고서 작업공간 안의 `자료에게 질문하기` 패널로 제공한다.

운영자는 현재 보고서 프로젝트에 포함된 소스에 대해서만 질문할 수 있다.

예시 질문:

- 이 섹션에 쓸 만한 성과 근거를 찾아줘.
- 출석률이 낮았던 세션만 정리해줘.
- 부모 사업 관련 일지에서 반복된 이슈가 뭐야?
- 성과조사 PDF에서 만족도 관련 수치를 찾아줘.
- 이 문단의 근거가 충분한지 확인해줘.

답변은 반드시 출처를 포함해야 한다. 운영자는 답변을 특정 섹션에 삽입할 수 있다.

전체 서비스 데이터 전체를 대상으로 하는 독립 AI 검색/조사실은 2차 범위로 둔다.

### 7. 전체 다시 생성

생성 완료 후 운영자는 전체 다시 생성을 할 수 있다.

정책:

- 전체 다시 생성만 허용한다.
- 다시 생성 전 기존 초안과 사용자 편집 내용이 덮어써질 수 있음을 경고한다.
- 섹션별 소스 재분석이나 새 자료 추가 후 증분 반영은 1차 범위에 포함하지 않는다.
- 새 자료를 추가해 다시 만들고 싶으면 새 보고서 프로젝트를 생성한다.

### 8. 내보내기

운영자는 생성 완료된 보고서를 DOCX와 PDF로 내보낼 수 있다.

DOCX는 운영자가 최종 서식과 문구를 마무리 편집하기 위한 파일이다. PDF는 공유와 제출 전 확인을 위한 파일이다.

HWP/HWPX export는 1차 범위에서 제외하고 2차 검토 대상으로 둔다.

## 출처와 신뢰성 요구사항

보고서 초안은 외부 제출에 쓰일 수 있으므로 출처 표시가 핵심 요구사항이다.

### 출처 표시 단위

주요 주장, 수치, 요약에는 문단 또는 주장 단위 출처를 표시한다.

출처 예시:

- 세션 기록: `2026-05-03 / 문해 사업 / 출석 12명 중 10명`
- 교육일지: `2026-05-03 문해 사업 교육일지`
- PDF 자료: `성과조사 결과.pdf p.7`
- 템플릿 참조: `2025 결과보고서 샘플.pdf 목차 p.2`

### 출처 확인 UX

운영자는 출처를 클릭해 원본 세션, 교육일지, PDF 페이지를 확인할 수 있어야 한다.

출처 없는 문장은 `확인 필요`로 표시한다. 사용자가 출처 없는 문장을 유지할 수는 있지만, export 전 경고를 보여준다.

### 확인 필요 항목

생성 완료 화면은 아래 항목을 보여줘야 한다.

- 출처 없는 문장
- 수치 검산이 필요한 문장
- 템플릿에는 있지만 채우지 못한 섹션
- 관련 자료가 부족한 섹션
- OCR 또는 PDF 분석 실패 파일
- 사용자가 직접 확인해야 할 해석성 문장

## 파일 정책

### 입력 형식

1차 MVP의 AI 분석 입력 형식은 PDF만 지원한다.

- 템플릿 PDF: 필수
- 기존 세션 첨부 PDF: 자동 수집 후보
- 보고서 전용 PDF: 추가 업로드 가능
- HWP/HWPX/DOCX/XLSX/이미지: 직접 분석 미지원, PDF 변환 안내

### 분석 상태

모든 PDF는 분석 상태를 가져야 한다.

- 대기 중
- 분석 중
- 분석 완료
- 분석 실패

분석 실패 시 운영자가 원인을 이해할 수 있는 메시지를 보여줘야 한다.

예시:

- 텍스트를 추출할 수 없습니다.
- OCR 처리에 실패했습니다.
- 파일 용량이 너무 큽니다.
- 암호화된 PDF는 분석할 수 없습니다.

### 삭제 정책

생성 전:

- 자동 수집된 자료는 제외할 수 있다.
- 보고서 전용 PDF는 삭제할 수 있다.

생성 중:

- 자료를 수정할 수 없다.

생성 완료 후:

- 소스 파일은 고정한다.
- 개별 파일 삭제는 제공하지 않는다.
- 보고서 프로젝트 전체 삭제는 가능하다.

보고서 프로젝트를 삭제하면 보고서 전용 PDF도 함께 정리한다.

기관 공용 자료실, 파일 재사용, 태그, 중복 관리는 1차 범위에서 제외한다.

## 권한 요구사항

1차 범위에서 보고서 작성 보조 기능은 기관 운영자만 접근할 수 있다.

권한 규칙:

1. 기관 운영자는 자기 기관의 보고서 프로젝트만 조회/생성/수정/삭제할 수 있다.
2. 기관 운영자는 자기 기관의 세션, 출석, 교육일지, 첨부 PDF만 소스로 사용할 수 있다.
3. 강사는 보고서 프로젝트에 접근할 수 없다.
4. 모든 보고서 프로젝트와 보고서 전용 PDF는 `organization_id` 범위 안에 있어야 한다.
5. AI 검색, PDF 추출, export 작업도 반드시 현재 기관 범위 안에서 실행되어야 한다.

## 개인정보와 안전 요구사항

보고서 소스에는 참여자 이름, 출석 정보, 상담성 메모, 조사 결과, 연락처 등 개인정보가 포함될 수 있다.

1차 MVP에서 최소 아래 원칙을 따른다.

1. 보고서 프로젝트는 기관 단위로 격리한다.
2. AI 답변은 현재 보고서 프로젝트에 포함된 소스만 사용한다.
3. 출처 없는 개인정보 추정 문장을 생성하지 않는다.
4. 원본 자료에서 확인되지 않은 민감 정보는 `확인 필요`로 표시한다.
5. 삭제된 보고서 프로젝트의 전용 PDF와 분석 결과는 재사용하지 않는다.
6. 사용자가 PDF 업로드 전에 개인정보 포함 가능성을 인지할 수 있게 안내한다.

## 사용자 스토리

1. 기관 운영자로서, 기존 결과보고서 샘플 PDF를 업로드하고 싶다. 그래야 기관이나 제출처의 양식에 맞는 보고서 초안을 만들 수 있다.
2. 기관 운영자로서, 보고서 대상 기간을 선택하고 싶다. 그래야 특정 운영 기간의 기록만 보고서에 반영할 수 있다.
3. 기관 운영자로서, 포함할 사업을 여러 개 선택하고 싶다. 그래야 하나의 결과보고서 안에 여러 세부 사업의 운영 결과를 담을 수 있다.
4. 기관 운영자로서, 시스템이 기간과 사업에 맞는 세션을 자동으로 찾아주길 원한다. 그래야 자료를 일일이 찾는 시간을 줄일 수 있다.
5. 기관 운영자로서, 자동 수집된 소스에서 일부 세션이나 PDF를 제외하고 싶다. 그래야 보고서에 맞지 않는 자료를 빼고 생성할 수 있다.
6. 기관 운영자로서, 보고서 전용 PDF를 추가 업로드하고 싶다. 그래야 만족도 조사, 사업 계획서, 외부 평가 자료 같은 별도 자료도 반영할 수 있다.
7. 기관 운영자로서, PDF 분석 상태를 확인하고 싶다. 그래야 어떤 자료가 보고서 생성에 실제로 반영되는지 알 수 있다.
8. 기관 운영자로서, 템플릿 PDF의 목차를 시스템이 분석해주길 원한다. 그래야 기존 보고서 구조를 새 보고서 초안에 반영할 수 있다.
9. 기관 운영자로서, 섹션별 초안을 자동 생성하고 싶다. 그래야 빈 문서에서 시작하지 않고 빠르게 검토할 수 있다.
10. 기관 운영자로서, 생성된 문단마다 근거 출처를 보고 싶다. 그래야 외부 제출 전 사실 확인을 할 수 있다.
11. 기관 운영자로서, 출처 없는 문장을 확인 필요로 보고 싶다. 그래야 AI가 근거 없이 만든 내용을 놓치지 않을 수 있다.
12. 기관 운영자로서, 원본 PDF 페이지나 세션 기록을 출처에서 바로 열어보고 싶다. 그래야 초안의 근거를 빠르게 확인할 수 있다.
13. 기관 운영자로서, 생성된 섹션 본문을 직접 수정하고 싶다. 그래야 기관의 문체와 실제 맥락에 맞게 보완할 수 있다.
14. 기관 운영자로서, 섹션을 더 공식적으로 다시 써달라고 요청하고 싶다. 그래야 제출용 문서 톤에 맞출 수 있다.
15. 기관 운영자로서, 특정 섹션을 더 짧게 요약하고 싶다. 그래야 분량이 긴 초안을 제출 양식에 맞출 수 있다.
16. 기관 운영자로서, 특정 섹션에 근거를 더 반영해달라고 요청하고 싶다. 그래야 주장이 빈약한 부분을 보강할 수 있다.
17. 기관 운영자로서, 보고서 자료에게 자유롭게 질문하고 싶다. 그래야 필요한 근거를 직접 찾아보지 않아도 된다.
18. 기관 운영자로서, 질문 답변을 특정 섹션에 삽입하고 싶다. 그래야 분석 결과를 보고서 초안에 빠르게 반영할 수 있다.
19. 기관 운영자로서, 초안이 마음에 들지 않으면 전체 다시 생성을 하고 싶다. 그래야 템플릿 분석이나 초안 방향이 잘못되었을 때 다시 시작할 수 있다.
20. 기관 운영자로서, 다시 생성 전 기존 편집 내용이 사라질 수 있음을 알고 싶다. 그래야 실수로 작업물을 덮어쓰지 않을 수 있다.
21. 기관 운영자로서, 완성된 초안을 DOCX로 내보내고 싶다. 그래야 최종 서식과 세부 문구를 문서 편집기에서 마무리할 수 있다.
22. 기관 운영자로서, 완성된 초안을 PDF로 내보내고 싶다. 그래야 공유하거나 제출 전 확인할 수 있다.
23. 기관 운영자로서, 보고서 프로젝트를 삭제하고 싶다. 그래야 잘못 만든 작업물을 정리할 수 있다.
24. 기관 운영자로서, 내 기관의 자료만 보고서 소스로 쓰이길 원한다. 그래야 다른 기관의 데이터가 섞이지 않는다.

## 구현 결정

### 새로 만들거나 확장할 주요 모듈

1. 보고서 프로젝트 관리
2. 템플릿 PDF 업로드와 분석
3. PDF 본문 추출과 OCR 처리
4. 운영 데이터 소스 자동 수집
5. 보고서 소스 선택/제외/추가 업로드
6. 섹션 구조와 초안 생성
7. 출처 연결과 확인 필요 항목 생성
8. 보고서 작업공간 UI
9. 자료에게 질문하기 패널
10. DOCX/PDF export

### 데이터 모델 방향

새로운 상위 `사업/프로젝트` 마스터 개념은 만들지 않는다.

보고서 프로젝트는 기존 기관, 사업, 세션, 출석, 교육일지, 첨부 문서와 연결된다. 보고서명, 제출처, 외부 사업명 같은 보고서 전용 정보는 보고서 프로젝트 자체에 둔다.

보고서 전용 PDF는 특정 보고서 프로젝트에만 연결한다. 기관 공용 자료실 개념은 만들지 않는다.

### AI 처리 방향

1. AI는 현재 보고서 프로젝트에 포함된 소스만 사용한다.
2. 템플릿 PDF는 구조, 문체, 분량 힌트로 사용한다.
3. 운영 데이터와 소스 PDF는 초안의 근거로 사용한다.
4. 주요 주장과 수치에는 출처를 연결한다.
5. 출처가 부족한 내용은 확정 문장처럼 숨기지 않고 확인 필요로 표시한다.

### UI 방향

보고서 작성 화면은 문서 편집기보다 작업공간에 가깝게 설계한다.

주요 UI는 아래로 구성한다.

- 보고서 프로젝트 목록
- 새 보고서 프로젝트 생성 폼
- 소스 자료 확인 화면
- 생성 진행 상태 화면
- 생성 완료 작업공간
- 섹션 편집 영역
- 출처/확인 필요 사이드 패널
- 자료에게 질문하기 패널
- export 액션

## 테스트 결정

테스트는 구현 세부가 아니라 외부 동작을 기준으로 작성한다.

우선 테스트해야 할 영역:

1. 기관 운영자만 보고서 프로젝트에 접근할 수 있다.
2. 보고서 프로젝트는 기관 범위 밖 데이터를 소스로 수집하지 않는다.
3. 기간과 포함 사업 기준으로 관련 세션/출석/교육일지/첨부 PDF가 수집된다.
4. 생성 전에는 소스 제외/추가/삭제가 가능하다.
5. 생성 중과 생성 완료 후에는 소스 파일이 고정된다.
6. 템플릿 PDF 분석 실패 시 사용자에게 복구 가능한 상태가 제공된다.
7. PDF 분석 실패 파일은 보고서 생성에 반영되지 않고 상태가 표시된다.
8. 초안 생성 결과에는 섹션, 본문, 출처, 확인 필요 항목이 포함된다.
9. 출처 없는 주요 문장은 확인 필요로 표시된다.
10. 자료에게 질문하기는 현재 보고서 프로젝트 소스 범위 안에서만 답한다.
11. 전체 다시 생성은 기존 초안 덮어쓰기 경고를 거친다.
12. DOCX/PDF export는 생성 완료 상태에서만 가능하다.

기존 코드베이스의 테스트 전례는 `src/server/services` 단위 서비스 테스트와 화면 동작 테스트를 참고한다. 보고서 프로젝트 수집/권한/상태 전이는 서버 서비스 단위 테스트로 먼저 고정하고, 작업공간의 핵심 사용자 흐름은 통합 또는 브라우저 테스트로 검증한다.

## 1차 범위

1차 MVP에 포함한다.

- 기관 운영자 전용 보고서 프로젝트
- 템플릿 PDF 필수 업로드
- PDF only 소스 분석
- 스캔 PDF OCR
- 기간/사업 기준 운영 데이터 자동 수집
- 기존 세션 첨부 PDF 자동 수집 후보
- 보고서 전용 PDF 추가 업로드
- 생성 전 소스 제외/추가/삭제
- 생성 중/생성 완료 후 소스 고정
- 템플릿 기반 섹션 초안 생성
- 문단/주장 단위 출처 표시
- 확인 필요 항목 표시
- 섹션 단위 편집
- 섹션 단위 AI 재작성
- 보고서 작업공간 안의 자료에게 질문하기
- 전체 다시 생성
- DOCX/PDF export
- 보고서 프로젝트 삭제

1차 MVP에서 제외한다.

## 남은 결정 사항

구현 전에 추가로 결정해야 할 사항:

1. PDF/OCR 처리에 사용할 기술 또는 외부 서비스
2. AI 모델과 비용 제한 정책
3. 파일 크기, 페이지 수, 보고서 프로젝트당 PDF 개수 제한
4. PDF 본문/청크/임베딩 저장 방식
5. AI 처리 실패 시 재시도 정책
6. DOCX/PDF export 품질 기준
7. 개인정보 포함 PDF에 대한 안내 문구와 보관 정책
8. 생성 완료 후 사용자가 직접 편집한 본문과 출처의 관계를 어떻게 표시할지
9. 출처 없는 문장의 export 전 경고 강도
10. 장기적으로 HWP/HWPX export를 지원할지 여부

## 요약

보고서 작성 보조 기능은 `dure`의 운영 기록 관리 기능 위에 올라가는 차별화 기능이다.

1차 목표는 기관 운영자가 기존 결과보고서 샘플 PDF를 템플릿으로 업로드하고, 기간과 사업을 선택해 관련 운영 기록과 PDF 자료를 자동 수집한 뒤, 출처가 달린 결과보고서 초안을 생성하는 것이다.

이 기능은 특정 기관에만 맞춘 고정 보고서 생성기가 아니라, 기관마다 다른 보고서 양식을 템플릿 PDF로 받아들이는 범용 보고서 작업공간이어야 한다.
